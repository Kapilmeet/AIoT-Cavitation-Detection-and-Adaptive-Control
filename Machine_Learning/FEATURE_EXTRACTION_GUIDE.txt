This directory contains classifier-ready feature tables built from the
team's own piezo and audio recordings of the pump test rig (the WBDB
dataset), plus documentation of the Random Forest model trained on them.


1. RAW DATA
------------
  Piezo   - 11 CSVs, one per (label, motor speed, take). Each row is
                one sample: Timestamp, A0_Raw, A1_Raw, A2_Raw, Motor_State.
                Recorded natively at 50,000 Hz (confirmed from the median
                inter-sample timestamp delta, 20 microseconds).

  Audio   - 12 CSVs, one per (label, motor speed, take). Each row is
                one sample: Timestamp, Audio_Raw (16-bit PCM amplitude).
                These were derived from the team's original .m4a phone
                recordings: the first 15 seconds of each .m4a was
                extracted, decoded to WAV at its native rate (16 kHz or
                48 kHz depending on the recording device), and then
                upsampled to 50,000 Hz with linear interpolation so the
                audio stream would share a common sample rate with the
                piezo stream. No samples were discarded in this step
                (upsampling only, since 50 kHz > both native rates).

  Labels: "normal"/"flow_normal" = healthy, "full" = cavitation,
  "partial" = partial_cavitation. Motor speed is 50% or 100%.

  Filenames follow <status>_motor_<speed>.csv, with a "(1)" suffix marking
  a second, independent recording take of the same condition.


2. FEATURE EXTRACTION PIPELINE (Raw -> Preprocessed)
------------------------------------------------------
Applied identically to every piezo channel (A0_Raw, A1_Raw, A2_Raw) and
the audio channel (Audio_Raw), entirely at each signal's native sample
rate - no resampling is performed at this stage.

  Step 1 - Frame segmentation
    Each channel is cut into non-overlapping 100 ms frames.
    At the native 50,000 Hz rate this is 5,000 samples/frame.
    Any leftover samples at the end of a recording that don't fill a
    complete 100 ms frame are dropped (a partial frame can't be windowed
    or FFT'd consistently with the rest).

  Step 2 - DC removal
    Each frame has its own mean subtracted from every sample in that
    frame.

  Step 3 - Windowing
    A periodic Hann window (5,000 samples, non-symmetric / "periodic"
    variant, i.e. scipy's sym=False) is applied to the DC-removed frame.

  Step 4 - FFT
    np.fft.rfft is run on the windowed frame. At 5,000 samples this
    returns 2,501 complex bins. np.fft.rfftfreq(5000, d=1/50000) gives
    the matching bin frequencies, 0 Hz to 25,000 Hz (the native Nyquist
    limit at 50 kHz), spaced 10 Hz apart.

  Step 5 - Power spectrum
    Power per bin = |rfft value|^2 (magnitude squared), so that energy
    can be summed additively across bins in the next step.

  Step 6 - Band-power features
    Power is summed into 20 linearly spaced bands spanning
    8,000 Hz - 20,000 Hz (np.linspace(8000, 20000, 21), i.e. 20 bands of
    600 Hz each). This range - not 0 Hz-Nyquist - was chosen deliberately:
    it targets the acoustic range where cavitation bubble-collapse
    crackle actually shows up, since most of the 0-8 kHz range is flow
    noise and motor/blade tones rather than cavitation signal. Bin
    energy outside 8-20 kHz is computed by the FFT but not included in
    any band.

    Result: one 20-number feature vector per channel per frame,
    regardless of that channel's native sample rate.

  This yields 60 feature columns for piezo (3 channels x 20 bands) and
  20 feature columns for audio (1 channel x 20 bands).


3. TRAIN / TEST SPLIT
-----------------------
The split is done per whole recording (never per frame), so that no
frame from the same physical recording ever appears in both the train
and test file for a given modality:

  - The base take of each (label, speed) combination -> train
  - The "(1)" duplicate take of the same combination     -> test

This mirrors a whole-condition holdout: an entire recording session is
assigned to one side of the split, not sampled frame-by-frame.

  NOTE ON CURRENT FILE STATE: as of this writing, test_audio.csv and
  test_piezo.csv contain rows from several "_base" group_ids that also
  appear in the corresponding train file (visible directly in the
  group_id column). That overlap was not present in the files as
  originally generated by this pipeline - something downstream has since
  re-split or resampled from the pooled frame pool. If bit-exact,
  leakage-free group isolation matters for evaluation, regenerate
  train/test from Raw/ using the group-based rule above before trusting
  test-set metrics.


4. OUTPUT FILES
-----------------
  train_piezo.csv, test_piezo.csv
    Columns: group_id, label, severity,
             piezo_ch1_band00..19, piezo_ch2_band00..19, piezo_ch3_band00..19
    (63 columns total: 3 metadata + 60 features)

  train_audio.csv, test_audio.csv
    Columns: group_id, label, severity,
             audio_ch1_band00..19
    (23 columns total: 3 metadata + 20 features)

  group_id  - <Modality>_<label>_motor<speed>_<base|dup>, identifies the
              source recording a frame came from.
  label     - healthy / cavitation / partial_cavitation
  severity  - motor_50 or motor_100 (the operating speed)

  Schema mirrors the per-modality feature tables (train_vibration.csv /
  train_electric.csv style) used for an earlier, separate public-dataset
  exercise in this project, for consistency.


5. RANDOM FOREST MODEL (train_fused_rf.ipynb)
-------------------------------------------------
This notebook (at the project root) trains two SEPARATE Random Forest
classifiers - one on audio features, one on piezo features - and
evaluates each against its own held-out test file. It does not combine
audio and piezo into a single feature vector; "Audio RF" and "Piezo RF"
are independent models trained and scored one modality at a time.

  Preprocessing before training:
    - Missing-value imputation: any NaNs in the feature columns are
      filled with that column's mean (fit on train, applied to test).
    - Z-score standardization: features are scaled with StandardScaler
      (fit on train, applied to test).

  Model configuration (identical for both models):
    RandomForestClassifier(
        criterion       = "gini",
        max_depth       = 12,
        min_samples_leaf= 5,
        ccp_alpha       = 0.001,
        n_estimators    = 100,
        random_state    = 42,
    )

  Evaluation: accuracy, precision/recall/F1 (weighted average across the
  three classes), and weighted one-vs-rest ROC AUC, plus a confusion
  matrix heatmap, computed on each modality's test CSV.

  Results as saved in the notebook:

    Audio RF  (test_audio.csv, 900 test frames)
      Accuracy            : 89.44%
      Precision (weighted): 0.8993
      Recall (weighted)   : 0.8944
      F1 (weighted)       : 0.8948
      ROC AUC (weighted)  : 0.9795
      Per-class (precision/recall/F1):
        cavitation          0.95 / 0.94 / 0.94  (support 300)
        healthy             0.92 / 0.83 / 0.87  (support 350)
        partial_cavitation  0.81 / 0.93 / 0.87  (support 250)
      Most influential bands: audio_ch1_band01-03 and band05 dominate
      feature importance - i.e. the lower part of the 8-20 kHz range
      (roughly 8.6-11.4 kHz) carries most of the discriminative signal
      for this model.

    Piezo RF  (test_piezo.csv, 24 test frames)
      Accuracy            : 87.50%
      Precision (weighted): 0.9125
      Recall (weighted)   : 0.8750
      F1 (weighted)       : 0.8644
      ROC AUC (weighted)  : 0.9623
      Per-class (precision/recall/F1):
        cavitation          1.00 / 0.93 / 0.96  (support 14)
        healthy             1.00 / 0.33 / 0.50  (support 3)
        partial_cavitation  0.70 / 1.00 / 0.82  (support 7)
      Most influential features are spread across piezo_ch1 and
      piezo_ch2 bands (no single band dominates as strongly as in the
      audio model); the healthy class has very few test examples (3),
      so its recall (0.33) is not statistically reliable.

  Caveat: the piezo test set is very small (24 frames total, only 3 of
  them healthy) because the raw piezo recordings themselves are short
  (well under 2 seconds each). Piezo metrics above should be read as
  indicative, not conclusive. The audio test set (900 frames, roughly
  balanced across classes) supports a more reliable estimate. Also see
  the train/test overlap note in section 3 - to the extent that overlap
  is present in the exact files the notebook was run against, the
  accuracy figures above may be somewhat optimistic relative to a
  genuinely held-out evaluation.


6. BRIEF DESCRIPTION & LIMITATIONS
-------------------------------------
  Description:
  The model takes 100-millisecond windows of vibration (piezo), current
  sensor data, and acoustic signals, extracts band-power features in
  the 8-20 kHz range (where cavitation bubble-collapse crackle is
  present), and classifies the pump's condition as healthy, partially
  cavitating, or fully cavitating. Two independent Random Forests were
  trained, one on audio features and one on piezo features (from the
  two vibration sensors) and current sensor data, rather than a single
  fused model.

  Limitations:
  The piezo model's 87.5% accuracy is not statistically reliable
  because its test set is small (only 3 healthy samples). The audio
  model (89% accuracy, ~900 balanced test samples) is more
  trustworthy. Both models are trained on a small, single-rig dataset,
  so they may not generalise to other pumps, sensor placements, or
  noise environments. The current sensor (A2_Raw) is used only to tag
  the motor speed state, not as a model input feature, so faults that
  only show up as current-draw anomalies would not be caught. There is
  also a known data-integrity issue: the current test files contain
  some samples from the same recordings used in training, so reported
  accuracies could be somewhat optimistic until the train/test split
  is regenerated cleanly.
